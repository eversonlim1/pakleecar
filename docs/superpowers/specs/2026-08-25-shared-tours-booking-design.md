# 셰어투어 콘텐츠 + 날짜별 예약 현황 시스템 — 설계 문서

날짜: 2026-08-25

## 배경

Pak. Lee's Car는 현재 10시간 프라이빗 카(운전기사 포함) 투어를 판매 중이다(index.html, 정적 사이트, Vercel 배포). 여기에 **셰어(합승) 투어** 상품을 신규 추가한다: 차량 렌트 비용을 여러 팀이 나눠 내는 개념으로, 인원이 많을수록 팀당 가격이 낮아진다.

3개 코스, 각 10시간:
1. 서울시내
2. 남이섬
3. DMZ

콘셉트상 "10시간 프라이빗 투어에 이어 두 번째로 중요한 상품"이므로 홈페이지 노출 위치를 상단부에 배치한다. 또한 날짜별로 몇 명이 예약했는지(좌석 단위) 공개적으로 보여주는 예약 현황 캘린더가 필요하다.

## 범위

이 스펙은 두 개의 하위 작업을 포함한다:
- **A. 셰어투어 콘텐츠/가격 섹션** (기존 정적 사이트에 섹션 추가 — bounded 성격이나 세부 규격은 이 문서에 포함)
- **B. 날짜별 예약 현황 시스템** (신규 백엔드 서브시스템)

두 작업은 독립적으로 배포 가능하지만 하나의 스펙으로 묶어 순서대로 구현한다 (A 먼저, B는 A의 캘린더 UI를 채워 넣는 후속 작업).

## A. 셰어투어 콘텐츠

### 코스별 동선 (10시간)

**1. 서울시내 코스**
- 광장시장 (전통시장, 길거리 음식)
- 경복궁 (조선 왕궁)
- 북촌한옥마을 (한옥 골목, 포토스팟) — *신규 추가*
- 명동 (쇼핑, 길거리 음식)
- 남산타워 (N서울타워, 야경)

**2. 남이섬 코스**
- 남이섬 (메타세쿼이아길, 셔틀선)
- 쁘띠프랑스
- 아침고요수목원
- 알파카월드 — *신규 추가 (춘천 인근 대표 결합 코스, Klook에서도 표준 콤보 구성으로 확인됨)*

**3. DMZ 코스**
- 임진각 / 자유의다리
- 제3땅굴
- 도라전망대
- ⚠️ **JSA(판문점 공동경비구역) 제외**: JSA는 여권 사전등록, 정부 승인 여행사의 지정 단체버스로만 진입 가능, UN/미군 에스코트 필수 등 자유 스케줄 프라이빗 카 콘셉트와 구조적으로 양립 불가. 기존 index.html의 "DMZ History Route" 카드에 있는 "JSA — Joint Security Area" 항목도 이번에 함께 수정한다.

### 가격 (팀 단위, 인원 구간별)

| 코스 | 4인 이하 | 5인 | 6-7인 |
|---|---|---|---|
| 서울시내 | ₩80,000 | ₩70,000 | ₩60,000 |
| 남이섬 | ₩100,000 | ₩90,000 | ₩70,000 |
| DMZ | ₩90,000 | ₩80,000 | ₩70,000 |

- 최소 4인 이상 출발 (인원 미달 시 미확정 상태로 남음 — 예약 현황 캘린더 참고)
- 가격은 **인당이 아니라 팀 전체 기준** (Private 투어와 동일하게 표기)
- Klook 등 경쟁 상품(가이드+입장료 포함 셰어투어, 인당 ₩50,000-190,000대)과 달리 Pak Lee's Car 셰어투어는 **교통(차량+운전기사)만 제공**, 가이드·입장료 미포함임을 명시 — 혼동 방지 문구 필수

### UI/배치

- 새 섹션 `<section id="shared-tours">`, 기존 `#pricing` 섹션과 `#airport` 섹션 사이에 배치
- 네비게이션(`.nav-links`, 모바일 메뉴)에 "쉐어투어" 링크 추가 (Harga와 FAQ 사이)
- 카드 스타일은 기존 `.tour-card` 톤을 재사용하되, 인원별 3단 가격 테이블을 카드 하단에 포함 (기존 `.price-table` 스타일 재사용)
- 각 카드 하단에 B의 예약 현황 캘린더로 연결되는 앵커/버튼 배치
- 3개 언어(ID/EN/TH) `data-id`/`data-en`/`data-th` 패턴 기존 코드와 동일하게 적용
- 기존 "DMZ History Route" 카드(#tours 섹션 내)의 JSA 항목을 3터널/도라전망대/임진각으로 교체

## B. 날짜별 예약 현황 시스템

### 데이터 모델 (Supabase Postgres)

테이블 `bookings`:
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid, PK | 자동 생성 |
| tour_date | date | 예약 날짜 |
| route | text | `seoul` \| `nami` \| `dmz` |
| pax | int | 해당 예약의 인원수 |
| note | text, nullable | 관리자 메모 (예: 고객명, 연락처) |
| created_at | timestamptz | 자동 생성 |

특정 날짜+코스의 상태는 저장하지 않고 **매번 합산해서 계산**한다:
- 합산 인원 0명: 표시 안 함(빈 날짜)
- 합산 인원 1-3명: "대기중 (N/8, 최소 4명 필요)" — 노란색
- 합산 인원 4-7명: "확정 (N/8)" — 초록색
- 합산 인원 8명: "마감" — 빨간색, 더 이상 예약 불가 표시

### 공개 캘린더 (홈페이지)

- A 섹션의 각 코스 카드 또는 별도 위치에 코스별 탭(서울/남이섬/DMZ) 월간 캘린더 위젯
- `GET /api/bookings?route=nami&month=2026-09` 호출 → 날짜별 합산 인원/상태 렌더링
- 날짜 클릭 시 상세 팝업: 현재 인원, 상태, "WhatsApp으로 문의하기" 버튼 (기존 wa.me 링크 패턴 재사용, 날짜/코스 사전 입력된 메시지)
- 과거 날짜는 회색 처리, 클릭 비활성화

### 관리자 페이지 (`/admin.html`)

- 비밀번호 입력 폼 (평문 비교 대신, 서버리스 함수에 비밀번호 전달 → 환경변수 `ADMIN_PASSWORD`와 비교 → 성공 시 랜덤 토큰 발급, `sessionStorage`에 저장해 이후 요청의 `x-admin-token` 헤더로 사용)
- 예약 목록 (날짜순, 코스 필터) + 인라인 수정/삭제
- 신규 예약 등록 폼 (날짜, 코스, 인원수, 메모)
- 별도 라우트로 npm 설치나 로그인 세션 관리 없이 단일 정적 HTML + fetch 호출로 구현 (프레임워크 도입 없음)

### API (Vercel 서버리스 함수, `/api/*.js`, Node 런타임)

- `GET /api/bookings?route=&month=` — 공개, 인증 불필요, 해당 월의 날짜별 합산 결과 반환
- `POST /api/bookings/login` — `{password}` → 성공 시 `{token}` 반환 (토큰은 랜덤 문자열을 서버 메모리가 아닌 `ADMIN_PASSWORD` 자체의 HMAC 등으로 검증 가능한 방식 사용 — 별도 세션 저장소 불필요)
- `POST /api/bookings` (관리자) — 예약 추가, `x-admin-token` 헤더 필요
- `PUT /api/bookings/:id` (관리자) — 예약 수정
- `DELETE /api/bookings/:id` (관리자) — 예약 삭제
- 모든 관리자 엔드포인트는 토큰 검증 실패 시 401 반환

### 배포/설정

- Supabase 프로젝트 신규 생성 (무료 티어), `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `ADMIN_PASSWORD`를 Vercel 환경변수로 등록
- 기존 정적 사이트 구조 유지, `/api` 디렉토리만 추가 (Vercel이 자동으로 서버리스 함수로 인식)
- Supabase RLS: `bookings` 테이블은 서버리스 함수(서비스 롤 키)에서만 쓰기 가능하도록 설정, 공개 API는 Supabase에 직접 접근하지 않고 반드시 `/api/bookings`를 경유

## 테스트 방침

- API 함수: 로컬에서 `vercel dev`로 구동 후 curl/Postman으로 각 엔드포인트 확인 (정상/인증실패/잘못된 날짜 등)
- 프론트: 브라우저에서 캘린더 렌더링, 언어 토글(ID/EN/TH), 모바일 반응형 확인
- 실사용 데이터로 검증하지 않음 — 반드시 테스트용 더미 예약 데이터로 확인 후 실제 배포 (기존 메모리 규칙: 실제 사용자 데이터로 검증 금지)

## 향후 고려사항 (이번 스펙 범위 밖)

- 고객이 직접 예약을 "요청"하는 폼 (현재는 캘린더 확인 후 WhatsApp으로 문의하는 흐름 유지)
- 예약 취소/변경 이력 관리
- 다국어 관리자 페이지 (관리자는 Pak Lee 본인만 사용하므로 인도네시아어/영어 중 택1로 충분, 이번엔 한국어 또는 영어로 단순 구현)
